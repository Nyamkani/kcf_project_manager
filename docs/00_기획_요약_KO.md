# KCF Project Manager — 기획 요약 (2026-11-27)

> **상태: 기획 단계 / 기능 미구현.** CLI 명령, Manifest 파일명, 내부 구현 API는 아직 확정하지 않았습니다.

## 배경: UGV02 개발 경험

UGV02에서는 Element마다 `main()` 구현 방식이 달랐고, 새 Element를 추가하려면 CMake Target, KCF Runtime bootstrap, Bringup `ElementSpec`, 인자/timeout 등을 직접 연결해야 했습니다. `bringup_main.cpp`와 Gateway 래퍼는 실제 애플리케이션 로직에 비해 상당한 설정·프로세스 관리 부담을 만듭니다.

**목표:** 사용자가 `Setup/Loop/Shutdown`, Driver, 알고리즘, FSM 같은 기능 구현에 집중할 수 있도록 표준 프로젝트 구조·생성·설정·빌드·실행을 지원합니다.

## 확정 설계 원칙

1. **STM32CubeMX와 유사한 Qt6 독립 Project Manager:** 프로젝트/Element를 생성하고 설정·구조를 관리합니다.
2. **편집은 VS Code/기존 IDE:** IDE, VS Code Extension, 자체 디버거/코드 편집기를 만들지 않습니다.
3. **CMake가 빌드의 기준:** 생성 결과는 독립적 표준 C++17/CMake 프로젝트입니다. Project Manager 없이도 VS Code CMake Tools의 Configure/Build(F7은 키 설정에 따름), `cmake --build`, target별 빌드가 정상 작동해야 합니다.
4. **colcon-like Headless CLI:** 전체/선택 Element 빌드·단독 실행·Supervisor 실행을 간편 명령으로 수행하지만, 새로운 컴파일러나 colcon 복제본을 만들지 않습니다.
5. **공통 계약:** Qt GUI/CLI는 동일 Project Model, Manifest, CMake, Launch Backend를 사용합니다.
6. **KCF Core API 변경 없음:** 기존 `ProcessElement`, `ProcessRuntime`, Bringup/Supervisor, IPC, Network, Gateway 계약을 재사용합니다.
7. **독립 버전:** Manager는 Core/Tools와 별도 개발·배포합니다. 공개 SDK/Bringup 계약이 호환된다면 Core 패치/마이너 버전 상승만으로 Manager 업데이트를 요구하지 않습니다. API/ABI 호환은 검증합니다.
8. **사용자 코드 보존:** Element 이름 변경·추가·삭제/제외, 설정 갱신 시 사용자 구현을 묵시적으로 덮어쓰지 않습니다. Stable ID, Diff Preview, 충돌 감지, 원자적 적용/롤백, 멱등성을 요구합니다.
9. **동일 Element 바이너리:** Standalone/Supervisor 모드에서 사용자 로직을 수정하지 않고 동일 실행 파일을 사용합니다.
10. **Gateway 독립성:** Host 단일 공유 Gateway(systemd 우선)를 Project Manager가 자동으로 Element 등록하거나 소유·중복 실행·종료하지 않습니다.

## 역할

| 구성 | 역할 |
| --- | --- |
| KCF Core | 공개 Runtime / Supervisor / IPC / Network SDK |
| KCF Project Manager | Qt6 GUI, CLI, Project Model, Generator, Manifest, CMake/Launch 연동 |
| KCF Tools | 실제 Runtime/Topic/Network 관측·Plot·제어 |
| VS Code / IDE | 사용자 C++ 코드 편집·디버깅·기본 CMake 빌드 |

## 개발 단계

- **M0:** Core v5.6.2 공개 SDK와 기존 `kcf` CLI 검토; 스키마/명령명/생성파일 정책 설계
- **M1:** 표준 CMake 프로젝트 + Element 생성, Native CMake/VS Code 빌드 검증
- **M2:** Manifest, Headless CLI, 단독 및 Supervisor 실행, Process Ownership/Log/Error
- **M3:** 공통 Backend를 사용하는 독립 Qt6 Project Manager GUI
- **M4:** 기존 프로젝트 가져오기, 안전한 Rename/Remove, Design Graph 고도화

MVP는 UGV02 형태의 Driver/MotionController/SensorProcessor 3-Element Fixture로 검증하고, 실제 UGV02 5-Element 구조를 확장 수용 사례로 사용합니다. 첨부 UGV02 소스 분석은 빌드/실물 검증과 구분합니다.
